# PortfolioSkills

이력서/포트폴리오 PDF를 수정하거나 만들 때 따르는 규칙.

## 1. 대상 문서

- 1.1 `Portfolio` 저장소 루트의 포트폴리오_Unreal_박인호.pdf, 포트폴리오_Unity_박인호.pdf
- 1.2 비공개 저장소 `https://github.com/inhopark/Resume`의 자기소개서_박인호.pdf, 경력기술서_박인호.pdf. 공개 저장소에는 다시 커밋하지 않는다.
- 1.3 모두 HTML을 헤드리스 Chrome으로 인쇄한 PDF다. 원본 HTML이 없으면 HTML 레플리카를 만들어 다시 렌더링한다.

## 2. 작업 절차

- 2.1 이력서 / 경력기술서 / 자기소개서 레플리카는 원본 톤을 따른다. (포트폴리오는 3번)
  - 어두운 타이틀, 초록(`#16794f` 계열) 포인트, 초록 사각형 숫자 섹션 배지
  - 옅은 초록 정보 카드, 초록 필(pill) 소제목 태그, `▸` 불릿
- 2.2 렌더링 명령. 경로는 `file:///C:/...` 형식으로 넘긴다(`/c/...`는 `ERR_FILE_NOT_FOUND`).

```
"C:\Program Files\Google\Chrome\Application\chrome.exe" --headless=new --disable-gpu --no-pdf-header-footer --print-to-pdf="<출력 경로>.pdf" "file:///<html 절대경로>"
```

- 2.3 내용을 고칠 때는 PDF를 만들기 전에 고친 내용을 `<원본명>_draft.txt` 텍스트 파일로 먼저 저장해 사용자가 빠르게 미리보게 한다. `_draft` PDF는 만들지 않는다.
  - 사용자가 내용을 확정하면 그때 원본 이름으로 PDF를 렌더링한다. (이전 원본은 git 기록으로 복구 가능)
  - `_draft.txt`는 좌우 스크롤 없이 읽히도록 한 줄을 한글 기준 약 35자(70칸) 이내로 줄바꿈한다.
- 2.4 `_draft.txt` 파일은 요청 전엔 커밋하지 않는다.
- 2.5 페이지 나눔 CSS는 최소로 건다.
  - 페이지보다 커질 수 있는 큰 컨테이너(`.company-block`, `.project`)엔 `break-inside: avoid`를 걸지 않는다. 통째로 밀려 큰 여백이 생긴다.
  - 제목류(`.tag`, `.project-title`, `.sub-title`, `.company-row`, `h3`)엔 `break-after: avoid`.
  - `break-inside: avoid`는 작은 단위(`ul.bullets li`, `.info-card`)에만.
- 2.6 폰트 크기는 경력기술서_박인호.pdf(2026-09 개정판) 기준을 따른다. 벗어나려면 먼저 확인한다.

| 요소 | 크기 / 굵기 |
|---|---|
| 본문 | 10pt, `line-height: 1.55` |
| 문서 타이틀(`h1`) | 22pt, 800 |
| 섹션 제목(`h2`) | 13pt |
| 섹션 배지(`.badge`) | 10pt, 700 |
| 프로젝트명(`.proj-title`) | 10.5pt, 700 |
| 스튜디오·기간(`.proj-meta`) | 8.5pt, 연회색 |
| 소제목 필 태그(`.subtag`) | 8.3pt, 700 |
| 작은 필 태그(`.tag`) | 7.8pt, 600 |
| 세부 불릿(`ul.bullets li`) | 9pt |

- 2.7 특정 섹션의 시작 페이지를 지정받으면 그 제목에만 `.page-start { break-before: page; }`를 건다.
  - 렌더링 후 목차(TOC)의 `p.N`이 맞는지 확인하고 필요하면 고친다.
  - 지정한 페이지에 안 들어가면 임의로 줄이지 말고 옵션(페이지 늘리기 / 섹션 쪼개기 / 그 구간만 폰트 축소 / 내용 축약)을 제시한다.
  - 폰트 축소는 그 구간 전용 클래스(예: `.proj-block.compact`)로만 한다.
- 2.8 수정했는데 PDF가 안 바뀌면 Chrome 캐시 문제다. `--user-data-dir`, `--disk-cache-dir`에 매번 다른 임시 경로를 주고, 끝나면 지운다.
- 2.9 포트폴리오_Unreal_박인호.pdf / 포트폴리오_Unity_박인호.pdf 중 하나를 고치면 다른 쪽도 같은 슬라이드 순서·내용인지 확인해 맞추고, 엔진별로 달라야 하는 부분만 다르게 둔다.
- 2.10 팁·목록을 정리할 때는 앞에 번호를 붙이고 항목마다 한 줄로 짧게 쓴다.
- 2.11 자기소개서는 제목 없이 주제별로 문단을 나누고, 문단마다 모든 문장이 주제에 맞는지 확인한다. 분량은 전체 글자 수만 맞춘다.

## 3. 포트폴리오_Unreal_박인호.pdf 디자인 기준

- 3.1 다크 테마 16:9 슬라이드. 원본 HTML이 없으니 기존 슬라이드 전체를 다시 만든 뒤 내용을 추가한다.
- 3.2 크기: 960 × 540pt, CSS `@page { size: 1280px 720px; margin: 0; }`, 슬라이드 1장 = 1페이지
- 3.3 배경 `#0a0d13` 계열 + 오른쪽 위 옅은 radial gradient, 포인트 민트 초록 `#2ee6a6` 계열, 보조로 파랑 / 노랑 / 회색 / 빨강 상단 띠 카드
- 3.4 폰트: 본문 맑은 고딕, 코드·터미널 박스 Consolas
- 3.5 구성: 자간 넓은 영문 섹션 라벨 → 흰색 굵은 제목 → 아이콘 목록 / 카드 그리드 / 초록 선 인용 박스 / 터미널 박스
- 3.6 마지막은 THANK YOU 페이지로 두고, 새 슬라이드는 그 앞에 넣는다.
- 3.7 다른 엔진으로 오해될 용어(예: unity build의 unity)는 쓰지 않고 풀어서 설명한다.
